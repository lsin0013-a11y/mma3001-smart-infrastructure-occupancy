# Performance study (G.20)

Generated by `python scripts/benchmark.py`. Times are the best of 3 runs (1 for the slow loop) on the author's laptop, so compare them with each other rather than as absolutes. Model training times are in `forecast_results.md`.

## 1. Interval integration (G.20, 5-min intervals)

1,894,867 events (occupancy pieces) integrated over 224,746 intervals.

| Method | Time (s) | Complexity |
|---|---|---|
| Python loop over pieces (reference) | 6.46 | O(n + m), interpreted |
| Cumulative sum + binary search (`_integrate`) | 0.081 | O(n + m log n), vectorised |

Speed-up: **79x**. Largest difference between the two: 0.00e+00 person (rounding only), so the fast method is verified against the reference.

Estimated work for the vectorised method: about 16 million operations (2 per piece for the cumulative sum; per boundary a binary search of log2(n) = 21 comparisons plus about 6 arithmetic operations, at 2 boundaries per interval) and about 71 MB of memory traffic, an arithmetic intensity of roughly 0.22 operations per byte. That is far below what a CPU core can compute per byte it loads, so the method is memory-bound: its 81 ms is set by moving the arrays, not by arithmetic. At 0.19 billion operations per second it runs well below a core's peak, consistent with that. The loop does a similar amount of arithmetic, but the Python interpreter adds about 3.4 microseconds of overhead per piece.

## 2. CO2 simulation: exact solution vs explicit Euler

One week at 1-min steps (10,080 steps), occupancy 0-11 people changing every 30 min, supply 10 L/s per person plus infiltration, room volume 810 m³.

| Method | Time (s) | Operations per step |
|---|---|---|
| Exact (analytical within each step) | 0.009 | about 4, plus one exp per step computed up front in a vectorised pass |
| Explicit Euler | 0.005 | about 5 |

Both are sequential loops, since each step needs the previous concentration, so their run times are similar and dominated by the interpreter. The difference is accuracy:

| Euler step (s) | Q·dt/V at peak flow | Max error vs exact (ppm) |
|---|---|---|
| 60 | 0.01 | 0.6 |
| 300 | 0.07 | 2.9 |
| 900 | 0.20 | 9.2 |
| 1800 | 0.39 | 20.4 |
| 3600 | 0.79 | 68.1 |
| 7200 | 1.58 | 221.8 |
| 10800 | 2.37 | 586.0 |

Euler's error grows roughly in proportion to the step (first-order method), and the method is only stable while Q·dt/V < 2, i.e. dt < 9,127 s at this peak flow. Past that limit (the 10800 s row) the solution overshoots and oscillates whenever the flow is high, and the error jumps; with a constant high flow it grows without bound (tested). The exact solution has no step-size error for piecewise-constant inputs and is unconditionally stable, so it is used for all results. Its result at a 1-min step and a 10-s step agree to machine precision (tested).
